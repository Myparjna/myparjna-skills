# 概览、使用与架构

只阅读本次涉及的文档章节，按项目实际内容填写。

### readme.md（项目概览）
- "这是什么"用一句话说清：给谁用、解决什么问题
- 技术栈直接抄 analysis-report.json，不要凭印象写版本号
- 快速启动命令必须逐条验证可行性
- 顶部"待确认问题"区汇总全部 `[需向交接人确认: ...]`，得到答复后同步更新正文
- "速查卡"必须是出事时 30 秒能扫完的卡：每格只放具体值（URL/端口/一行命令/人名），禁止长句和概念描述；细节写在对应文档里

### usage.md（项目使用说明）
- 从真实用户角色出发，写清入口、权限、输入、操作步骤、输出和失败表现
- 界面项目必须依据真实浏览器/软件操作；CLI、嵌入式和推理项目写真实命令、设备连接和数据路径
- 启动说明不能代替使用说明，按实际业务覆盖核心流程，不设最少数量

### architecture.md（系统架构）
- 架构图用 mermaid，标出数据流向（用户 → CF Pages → Workers → D1/外部 API）
- 目录结构为 实际存在的关键目录各加一行用途说明
- Monorepo 需说明各 workspace 职责划分

### architecture.md 内的模块说明
- 模块按业务职责划分，不要把每个源文件都当成模块
- 每个模块写清职责、入口、上游、下游、关键配置、共享状态和测试位置
- 给出实际存在的关键调用链，不设最少数量，并引用实际源码路径
