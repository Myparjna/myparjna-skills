# Frontend Design Ultra

以设计总监的标准做前端界面。本技能建立在两条核心原则之上：

1. **排除 AI 俗套**：模型生成界面有统计性的默认答案（配色、版式、文案、动效各有一套套路）。凡是未经思考就落进套路的选择，一律重来。清单见 `references/anti-slop-checklist.md`。
2. **规范布局与前端常识**：布局、间距、导航、组件、触控、可读性有成熟的工程规范，先把这些做对，再谈风格表达。规范参考已内置于 `references/harmony/`（华为 UX 指南通用部分）。

**一句话工作方式：先判形态，再立合同；布局从任务推，风格从题材推；大胆只花一处，验证分级有界。**

## 优先级仲裁（冲突时从高到低）

1. **用户的明确需求与提示词**——钉死的方向严格照做，本技能所有负面清单自动豁免。
2. **项目现有视觉体系**——已有设计系统、品牌规范、页面结构时，局部修改保持原有语言，不擅自重设计。
3. **本技能默认偏好**——只在以上两层没覆盖的自由度上生效。

### 新项目默认值

- 默认日间/浅色主题，适用于工作台、移动端、落地页；不自动增加主题切换。数据大屏默认深色底（指挥室弱光环境与远观可读性的业务惯例，不算 B 级风险，无需写保留理由），色板按业务内容、品牌与可读性选择，避免纯黑。用户明确主题或已有项目体系优先。
- 中文正文默认用系统字体栈（`-apple-system, "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`），不下载网页字体：一份中文字体档动辄 5MB 上下，正文全量引入会拖慢首屏并挤占同期网络请求。只有当标题、主视觉、品牌位等少量文字确实需要设计感，或用户明确要求指定字体时，才经 CDN 引入，且只声明实际用到的 1–2 档字重、只作用于这些元素，正文继续走系统栈。字重按实际用到的档位声明，只使用已加载的字重；缺哪个粗度就补哪个文件，不靠浏览器合成粗体加粗，合成粗体显重、发虚、边缘发糊。
- 补全主任务需要的功能和状态，不为“丰富”增加无关地图、视频、图表、账号或设置入口。
- 标题位置按形态决定：展示型数据大屏总标题默认相对整个画布水平居中；工作台页面标题跟随内容起始轴。模块标题不随总标题一律居中，“居中 Hero”审美提示不适用于大屏总标题。
- 工作台默认保持简洁：次要解释按需显示，短说明用 Tooltip，长说明用可点击展开的帮助；必要输入条件、错误和影响决策的信息保持简短可见。具体规则见 `references/progressive-help.md`。
- 新建站点提供可识别的 favicon；优先已有品牌图标，无素材时按 `references/site-icon.md` 生成本地 SVG，不能留作浏览器默认地球图标。

## 何时使用

新建或改造任何有视觉表现的界面。不适用：纯后端逻辑、无界面脚本。

## 工作流

### 第 0 步：形态判定与分流

**形态不同，设计流程不同，先判定再进入对应专项：**

| 主形态 | 判定特征 | 专项流程 |
|---|---|---|
| 移动端 H5 | 手机浏览器/微信内打开，触控，≤430px | `references/page-mobile-h5.md` |
| 桌面工作台/后台 | PC 键鼠，长时间任务操作，≥1280px | `references/page-workbench.md` |
| 数据大屏 | 固定分辨率，远观轮播，少交互 | `references/page-data-screen.md` |
| 官网/落地页 | 首次访问，说服转化 | `references/page-landing.md` |

**扩展形态参照最近的主形态流程，只按下表改关键差异：**

| 扩展形态 | 判定特征 | 参照 | 关键差异 | 风格取向默认 |
|---|---|---|---|---|
| 表单/设置/详情页 | 后台内以填写、编辑、查阅记录为主 | 工作台 | 分组分栏、标签对齐方式统一、校验反馈就近显示、危险提交防误触、未保存离开提示 | 3/2/6 |
| 演示页（PPT 式） | 配合演讲或自助翻页浏览 | 落地页 | 一页一个观点，正文 ≥24px，图表就地放大，动效服务演讲节奏不炫技，支持键盘翻页与页码 | 6/4/2 |
| 封面/海报 | 公众号封面、活动海报、报告封面 | 落地页 Hero | 单焦点大标题，一眼可记，按目标比例固定画布，无导航无表单，导出分辨率给足 | 7/2/1 |
| 流程图/图解页 | 架构图、业务流程、关系拓扑 | 工作台 | SVG 节点连线优先，流向一致、层级可数、配图例，支持缩放拖动，节点可点击查看详情 | 4/3/6 |
| 长文/文档页 | 文章、帮助文档、报告正文 | 排版可读为主 | 行长 45–75 字、行高 ≥1.6、目录锚点、代码块与正文区分、打印友好 | 3/1/5 |
| 登录/门禁页 | 只完成一个认证或准入动作 | 表单页思路 | 单焦点表单，错误就地提示，背景从 WORLD 取材质，不堆营销内容 | 4/3/2 |

仍不在表内的页面按访客成功判定分流：完成任务=Operate 参照工作台；被打动=Persuade 参照落地页；理解内容=Read 以排版可读性为主。

形态决定成功标准。判错形态是一切乱的根源：给工作台用落地页手法，得到花哨难用的工具；给大屏用工作台密度，远观一片模糊；给演示页用文档密度，后排观众什么都看不清。

### 第 1 步：方向合同（写代码前落笔，中途不漂移）

```
THESIS（主张）: 这一页的一句话设计主张。
WORLD（世界）:  题材世界——行业、材质、器物、语汇，风格的来源。
MODE（形态）:   形态判定结果（主形态或扩展形态）+ 对应成功标准。
STYLE（风格取向）: 布局胆量 1-10 / 动效强度 1-10 / 信息密度 1-10。
MEMORY（记忆点）: 全页至多一个让人记住的东西；工作台/大屏允许没有。
```

- 色板、字体、材质、图形语言从 WORLD 推导，不从"上次做过的好看页面"平移。
- 风格取向先按第 0 步判定出的形态给默认值：工作台 5/3/7，落地页 7/6/4，大屏 4/3/8，移动 H5 4/3/5，扩展形态默认值见第 0 步分流表。形态拿不准时，结合用户的使用环境与流程（谁在用、在什么设备上看、要完成什么事）再定。默认值只是起点：对默认的布局、动效、密度不满意可以明说调整，用户明确要求优先。
- MEMORY 是大胆的唯一去处，其余全部克制。口诀：出门前摘一件首饰。

填写示例（巡检告警移动 H5）：

````
THESIS: 值班员单手 30 秒内判断一条告警的真伪并完成处置。
WORLD:  工厂安监——巡检点位、摄像头证据、工单流转；语汇克制、工业感。
MODE:   移动 H5——主任务收敛、拇指可达、弱网可用。
STYLE:  4/3/5（形态默认值，不额外加戏）。
MEMORY: 无；告警卡状态色条承担识别，不为记忆点加装饰。
````

要点：THESIS 写可验证的行为结果，不写风格形容词；WORLD 写取材来源，后续色板字体都能从它推出来；MEMORY 允许为空。

多页面项目先读取已有设计说明；无既有位置时，将确定的共用色板、字体角色、间距、控件、层级、状态与页面差异写入 `ProjectDoc/前端设计说明.md`。后续页面先读取再扩展，局部修改不覆盖已有决策。简单单页或仅输出代码的任务可在工作计划中简记，不额外增加文档。设计过程说明不放入产品界面。

### 第 2 步：任务 → 信息优先级 → 布局（先于视觉决策）

布局从任务推导，不从模板推导。依次回答：

1. 用户进入本页，首先要看什么、做什么？
2. 哪些信息需要同时比较？哪些只在操作后需要？
3. 筛选、结果、详情之间是什么关系？

按答案选结构（形态专项文件里有各自的完整模式库）：

| 任务特征 | 可选结构 |
|---|---|
| 频繁检索、筛选、看详情 | 筛选区＋结果区＋按需详情面板 |
| 比较多条同类记录 | 表格或对齐列表（不用卡片堆） |
| 逐项处理任务（告警/工单） | 优先级列表＋详情＋就近操作 |
| 同时监看空间与异常 | 地图/视频主区＋异常队列＋次要统计 |
| 说服并完成一个动作 | Hero＋价值＋证据＋行动 |

选定后画 ASCII 线框，标出对齐轴。结构确认前不动配色字体。

上表均为候选：需要定位、分布或路径分析且有位置数据时用地图；需要查看现场画面或影像证据时用视频；只有明确三维空间任务时才用 3D。无这些任务时以指标、趋势、对比、进度或列表组织内容，不预留空的中央媒体区。

### 第 3 步：设计计划（紧凑 token 系统）

1. **色彩**：先确定约 4–6 个基础命名色，再按需补齐文字、边框、语义与图表色，不把 6 色当整个系统上限。一个主强调色；语义色守惯例（红=错误、绿=成功、黄=告警、蓝=信息）；深浅主题遵循新项目默认值（工作台/移动端/落地页浅色，数据大屏深色），不另设第三套约定。
2. **字体**：1–2 个家族加角色（展示/正文/数字）。数字一律等宽或 `tabular-nums`。装饰字体只用于标题层级，正文表格用正文无衬线。
3. **间距刻度**：优先 `4/8/12/16/24/32/48/64`，密度高取小档、密度低取大档，复用项目刻度；安全区、媒体比例和响应式计算允许必要例外。
4. **默认答案复检**：逐部分检查选择是否有任务依据。相似任务允许复用成熟结构；缺乏依据、仅为装饰的部分才重写，记录原因。

### 第 4 步：反俗套分级检查

过 `references/anti-slop-checklist.md`：

- **A 级质量要求**（无 lorem、无死按钮、无 emoji 图标、对比度达标、相关状态完整、信息不重复等）：发现缺陷直接修复，适用范围与豁免按优先级仲裁处理，不能仅因审美偏好免除必要行为。
- **B 级审美风险提示**（米色衬线赤陶橙、居中 Hero、三等分卡片、AI 紫蓝、辉光粒子等）：命中需写一句保留理由，写不出就换。需求点名的直接用。

### 第 5 步：规范构建（质量底线）

**通用底线（四形态共守）：**

- 页面头完整：`lang="zh-CN"`、charset、可区分多项目的 title；移动端必须声明 `<meta name="viewport" content="width=device-width, initial-scale=1">`，缺失会渲染成缩小的桌面版。内容图写 alt，纯装饰图用空 alt。
- 对齐即秩序：同列元素共享对齐轴；间距走第 3 步刻度；多列结构用 CSS Grid，不用 flex 百分比凑数。
- 工作台双栏要兼顾内容长度与操作位置：避免一侧不断向下堆叠、另一侧大面积闲置，导致主要操作落到很下面。先调整分区、间距与次要内容的展开方式，不靠拉高空面板或塞入无关内容凑等高；具体按工作台专项流程检查。
- 触控目标移动端 ≥44×44px、桌面 ≥32px；按钮主次分明，按交互提供 hover/active/disabled，异步动作增加 loading，不给普通导航制造加载过程。
- 表单 label 在输入框上方，错误就近提示，不用 placeholder 冒充 label。
- 异步或可变数据区按实际情况设计 loading/empty/error；静态内容不制造三态。有表单、检索、删除或提交时读取 `references/interaction-states.md`，实现输入保留、重试、撤销和关联数据更新。
- 图标从 Tabler / Lucide / Iconify 等主流库中选一套作为主库，经 CDN 加载（图标字体或图标库运行时组件），按 `references/font-icon-selection.md` 核对 CDN 与授权；不手写、不手绘、不凭几何印象拼 SVG 图形，也不手工抄 path 进页面；描边和视觉尺寸统一；语义色 + 文字/图标双通道表达状态。
- 动效只动 `transform`/`opacity`，交互反馈 150–300ms，缓出 `cubic-bezier(0.16,1,0.3,1)`，尊重 `prefers-reduced-motion`，保留可见焦点。循环动效只服务于加载与刷新过程（spinner、骨架屏），过程结束即停；在线、存活、实时、连接正常这类状态用静态的色、形、文字表达，不加循环闪烁、呼吸或跳动的红点，也不给严重度色条、卡片边框、标题等常驻元素加周期性明暗动画（需要表达告警等级或时效时用静态分级色与形状，大屏点位注意力动效按其形态专项条款处理）。
- 文案主动语态说人话：按钮写动作、错误写原因和补救；业务语汇具体真实。
- 数据可信：汇总与分项对得上账，百分比标基数，趋势标时间范围；模拟数据允许标注模拟。
- 技术栈尊重：按项目现有框架与构建方式实现。单文件 HTML、指定地图库、固定分辨率缩放等属于**项目约定**，仅当项目明确要求时执行；大屏固定画布缩放比按 `min(可用宽/画布宽, 可用高/画布高)` 双向计算。
- 视频、监控画面、视频封面按 `references/media-ratios.md` 使用 16:9、4:3、1:1、9:16 等常见比例，禁止为了塞满布局生成随意的窄条或扁长画面；地图与图表不套用视频比例。
- 外部资源（地图瓦片、图片、字体、脚本）的加载判定按网络真实耗时设计：只要有任一资源加载成功就撤销"加载中/失败"提示并正常呈现；失败判定依据明确的错误（HTTP 错误、`onerror`、库未加载、确无任何资源返回），不用固定短超时把"慢"判成"失败"。等待时间给足（同一页面常同时拉取字体、大图、瓦片、脚本，冷缓存下整页可能十几秒），超时后保留可点击重试入口，失败或未就绪不阻塞其余内容展示。地图瓦片优先免 Key 且已验证稳定的来源，需要 API Key 或来源不稳定的不默认采用；页面中非首屏必需的外部资源延后加载，控制同期请求总量。
- 视频保持净画面：正常播放直接呈现源视频，不额外添加 LIVE、在线标记、红点、时钟、点位名称或装饰遮罩，也不把这些内容移到画面外重复显示。无法播放时用黑色画面区域内的空状态图标与必要短提示表达；源视频或 MP4 自带的时间、点位、水印原样保留，详见 `references/media-ratios.md`。

**字体与图标资源流程**（需要中文网页字体/图标 CDN 时）：

1. `online-fonts-icons` 技能可用时：加载它并按 `references/font-icon-selection.md` 的索引实际读取正文、标题和图标参考；不能只读技能简介，也不一次加载全部资源。
2. 该技能不可用（如隔离环境）时直接用以下候选，不要反复犹豫或自行发明方案：
   - 中文正文：默认系统字体栈（`-apple-system, "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`），不引 CDN 字体；标题、主视觉或品牌位确需设计感时，才从 `references/font-icon-selection.md` 自包含候选段取一档字体，只作用于这些元素。不猜包名，候选尝试不超过 2 个地址即沿回退链下行；数字与代码用等宽字体（如 JetBrains Mono）或 `tabular-nums`。
   - 图标：Tabler / Lucide / Iconify 任选一套主库，确切引入地址与三种可用方式见 `references/font-icon-selection.md` 的自包含候选段，直接取用并核对图标名；图形取自图标库，不按几何印象自行绘制。
   - 以上均不可达时，用系统字体栈完成本页，并在交付说明中标注。
3. 逐款核对商用授权与版本（"收录在免费资源里"不等于授权确认）；CDN 锁版本后核对具体图标名在该版本存在（图标库不同版本图标名有增删，凭印象写容易出现空白方框）。
4. `font-family` 名以 CDN 的 `@font-face` 实际声明为准，配 `font-display: swap` 与西文 fallback。
5. 用目标中文调用 `document.fonts.load()`，确认返回非空 FontFace 且状态为 loaded，并通过 DevTools Rendered Fonts 核对实际字形；仅 Promise 成功或 `document.fonts.check()` 为 true 不能证明目标字体生效。回退时如实记录。

排查控制台错误、意外横向溢出、资源加载、控件行为、相关状态与键盘可达。字体/图片不可用时验证回退并说明。除截图外，至少实际操作主流程及主要失败恢复路径；检查短文字意外换行、输入框挤压、图标文字重叠、固定栏遮挡及视频比例。移动 H5 另按目标容器验证：微信内置浏览器或对应移动 UA 下的布局、安全区与键盘弹出行为。截图不能替代操作验证。

分段生成或多次编辑落盘的文件，验证前先通读拼接处：逐段 Edit 之后重读接缝前后约 10 行，确认 `<script>`/`<link>` 等关键标签没有整段丢失或重复——部分功能存活（如时钟在走）不能证明同文件其他块（如地图库标签）存在；Edit 锚点引用注释或邻接标签时，先确认锚点在磁盘上仍存在再编辑。

**验证工具注意事项（避免为工具假象改代码）：**

- CDN 资源做内容级检查，不只看 HTTP 200：地图瓦片、图链可能返回 200 但实为带水印的错误占位图；字体 CSS 可达不等于字形生效。下载实际资源目检或截图确认。
