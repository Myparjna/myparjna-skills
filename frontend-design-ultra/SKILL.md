# Frontend Design Ultra

以设计总监的标准做前端界面。本技能建立在两条核心原则之上：

1. **排除 AI 俗套**：模型生成界面有统计性的默认答案（配色、版式、文案、动效各有一套套路）。凡是未经思考就落进套路的选择，一律重来。清单见 `references/anti-slop-checklist.md`。
2. **规范布局与前端常识**：布局、间距、导航、组件、触控、可读性有成熟的工程规范，先把这些做对，再谈风格表达。规范参考见 `references/harmony/INDEX.md`。

**一句话工作方式：先判形态，再立合同；布局从任务推，风格从题材推；大胆只花一处，验证分级有界。**

## 优先级仲裁（冲突时从高到低）

1. **用户的明确需求、提示词与用户级规则**（如 AGENTS.md 中的主题约定）——钉死的方向严格照做，本技能所有负面清单自动豁免。
2. **项目现有视觉体系**——已有设计系统、品牌规范、页面结构时，局部修改保持原有语言，不擅自重设计。
3. **本技能默认偏好**——只在以上两层没覆盖的自由度上生效。

### 新项目默认值

- **主题**：默认日间/浅色主题，不自动增加主题切换。数据大屏在上两层未约定主题时默认深色底（指挥室弱光环境与远观可读性的业务惯例，不算 B 级风险），色板按业务内容与可读性选择，避免纯黑；用户规则要求只做日间模式时，大屏同样使用浅色主题。
- **中文字体**：正文用系统字体栈，不下载网页字体（一份中文字体档约 5MB，会拖慢首屏）。只有标题、主视觉、品牌位确需设计感或用户指定字体时才经 CDN 引入，且只声明实际用到的 1–2 档字重、只作用于这些元素。字体栈、候选地址与字重规则见 `references/font-icon-selection.md`。
- **功能范围**：补全主任务需要的功能和状态，不为“丰富”增加无关地图、视频、图表、账号或设置入口。
- **标题位置**：展示型数据大屏总标题相对整个画布水平居中；工作台页面标题跟随内容起始轴；模块标题不随总标题居中。
- **工作台简洁**：次要解释按需显示，短说明用 Tooltip，长说明用可展开帮助；必要输入条件、错误和影响决策的信息保持简短可见。见 `references/progressive-help.md`。
- **favicon**：新建站点提供可识别的 favicon，优先已有品牌图标，无素材时按 `references/site-icon.md` 生成本地 SVG。

## 工作流

### 第 0 步：形态判定与分流

**形态不同，设计流程不同，先判定再进入对应专项：**

| 主形态 | 判定特征 | 专项流程 |
|---|---|---|
| 移动端 H5 | 手机浏览器/微信内打开，触控，≤430px | `references/page-mobile-h5.md` |
| 桌面工作台/后台 | PC 键鼠，长时间任务操作，≥1280px | `references/page-workbench.md` |
| 数据大屏 | 固定分辨率，远观轮播，少交互 | `references/page-data-screen.md` |
| 官网/落地页 | 首次访问，说服转化 | `references/page-landing.md` |

**扩展形态参照最近的主形态流程，只按下表改关键差异：**

| 扩展形态 | 判定特征 | 参照 | 关键差异 | 风格取向默认 |
|---|---|---|---|---|
| 表单/设置/详情页 | 后台内以填写、编辑、查阅记录为主 | 工作台 | 分组分栏、标签对齐方式统一、校验反馈就近显示、危险提交防误触、未保存离开提示 | 3/2/6 |
| 演示页（PPT 式） | 配合演讲或自助翻页浏览 | 落地页 | 一页一个观点，正文 ≥24px，图表就地放大，动效服务演讲节奏不炫技，支持键盘翻页与页码 | 6/4/2 |
| 封面/海报 | 公众号封面、活动海报、报告封面 | 落地页 Hero | 单焦点大标题，一眼可记，按目标比例固定画布，无导航无表单，导出分辨率给足 | 7/2/1 |
| 流程图/图解页 | 架构图、业务流程、关系拓扑 | 工作台 | SVG 节点连线优先，流向一致、层级可数、配图例，支持缩放拖动，节点可点击查看详情 | 4/3/6 |
| 长文/文档页 | 文章、帮助文档、报告正文 | 排版可读为主 | 行长 45–75 字、行高 ≥1.6、目录锚点、代码块与正文区分、打印友好 | 3/1/5 |
| 登录/门禁页 | 只完成一个认证或准入动作 | 表单页思路 | 单焦点表单，错误就地提示，背景从 WORLD 取材质，不堆营销内容 | 4/3/2 |

仍不在表内的页面按访客成功判定分流：完成任务=Operate 参照工作台；被打动=Persuade 参照落地页；理解内容=Read 以排版可读性为主。

形态决定成功标准。判错形态是一切乱的根源：给工作台用落地页手法，得到花哨难用的工具；给大屏用工作台密度，远观一片模糊；给演示页用文档密度，后排观众什么都看不清。

形态判定的同时定下栅格骨架：工作台用 CSS Grid，列数 8/12/16/24 按内容密度选、同页只用一档；移动 H5 单列、左右边距统一 16；大屏默认自适应布局；落地页 12 列内自由跨列。

### 第 1 步：方向合同（写代码前落笔，中途不漂移）

```
THESIS（主张）: 这一页的一句话设计主张。
WORLD（世界）:  题材世界——行业、材质、器物、语汇，风格的来源。
MODE（形态）:   形态判定结果（主形态或扩展形态）+ 对应成功标准。
STYLE（风格取向）: 布局胆量 1-10 / 动效强度 1-10 / 信息密度 1-10。
MEMORY（记忆点）: 全页至多一个让人记住的东西；工作台/大屏允许没有。
```

- 色板、字体、材质、图形语言从 WORLD 推导，不从“上次做过的好看页面”平移。
- 风格取向默认值：工作台 5/3/7，落地页 7/6/4，大屏 4/3/8，移动 H5 4/3/5，扩展形态见第 0 步分流表。拿不准时结合谁在用、在什么设备上看、要完成什么事再定；用户明确要求优先。
- MEMORY 是大胆的唯一去处，其余全部克制。口诀：出门前摘一件首饰。

填写示例（巡检告警移动 H5）：

```
THESIS: 值班员单手 30 秒内判断一条告警的真伪并完成处置。
WORLD:  工厂安监——巡检点位、摄像头证据、工单流转；语汇克制、工业感。
MODE:   移动 H5——主任务收敛、拇指可达、弱网可用。
STYLE:  4/3/5（形态默认值，不额外加戏）。
MEMORY: 无；告警卡状态色条承担识别，不为记忆点加装饰。
```

要点：THESIS 写可验证的行为结果，不写风格形容词；WORLD 写取材来源；MEMORY 允许为空。

多页面项目先读取已有设计说明；无既有位置时，将共用色板、字体角色、间距、控件、层级、状态与页面差异写入 `ProjectDoc/前端设计说明.md`。后续页面先读取再扩展，局部修改不覆盖已有决策；同一组件跨页复用同一套 class 或 token。简单单页任务在工作计划中简记即可。设计过程说明不放入产品界面。

### 第 2 步：任务 → 信息优先级 → 布局（先于视觉决策）

布局从任务推导，不从模板推导。依次回答：

1. 用户进入本页，首先要看什么、做什么？
2. 哪些信息需要同时比较？哪些只在操作后需要？
3. 筛选、结果、详情之间是什么关系？

按答案选结构（形态专项文件里有各自的完整模式库）：

| 任务特征 | 可选结构 |
|---|---|
| 频繁检索、筛选、看详情 | 筛选区＋结果区＋按需详情面板 |
| 比较多条同类记录 | 表格或对齐列表（不用卡片堆） |
| 逐项处理任务（告警/工单） | 优先级列表＋详情＋就近操作 |
| 同时监看空间与异常 | 地图/视频主区＋异常队列＋次要统计 |
| 说服并完成一个动作 | Hero＋价值＋证据＋行动 |

选定后在第 0 步的栅格骨架上画 ASCII 线框，标出主对齐轴。结构确认前不动配色字体。

地图只在需要定位、分布或路径分析且有位置数据时使用；视频只在需要现场画面或影像证据时使用；3D 只在明确的三维空间任务中使用。无这些任务时以指标、趋势、对比、进度或列表组织内容，不预留空的中央媒体区。

### 第 3 步：设计计划（紧凑 token 系统）

1. **色彩**
   - 先确定约 4–6 个基础命名色，再按需补齐文字、边框、语义与图表色；一个主强调色；语义色守惯例（红=错误、绿=成功、黄=告警、蓝=信息）。
   - 文字灰度三级（主/次/辅），可用 Tailwind 灰阶（浅色 900/600/500，深色 200/300/400），三级均满足 WCAG AA（正文 ≥4.5:1）。浅色主题 gray-400 对白底约 2.8:1，只用于占位符与禁用态；辅助级不承载关键信息。
   - 背景至少两层（页面底与卡片/面板面，悬停或选中再一级），深色大屏同样分层。
2. **字体**：1–2 个家族加角色（展示/正文/数字）；数字一律等宽或 `tabular-nums`；装饰字体只用于标题。字阶默认对齐 Tailwind 刻度：12 / 14–16 / 18–20 / 24–36，大屏按形态放大。项目使用 UI 组件库（Element Plus、Ant Design、Arco、Naive UI 等）时优先遵循其主题变量。相邻层级不跳两档以上；行高 1.5–1.7（大标题 1.2–1.3），正文行长 45–75 字。
3. **间距刻度**：优先 `4/8/12/16/24/32/48/64`，密度高取小档、密度低取大档，复用项目刻度。
4. **默认答案复检**：逐部分检查选择是否有任务依据。相似任务允许复用成熟结构；缺乏依据、仅为装饰的部分才重写。

### 第 4 步：反俗套分级检查

过 `references/anti-slop-checklist.md`：

- **A 级质量要求**（无 lorem、无死按钮、无 emoji 图标、无角标装饰条、对比度达标、相关状态完整、信息不重复等）：发现缺陷直接修复，不能仅因审美偏好免除必要行为。
- **B 级审美风险提示**（米色衬线赤陶橙、居中 Hero、三等分卡片、AI 紫蓝、辉光粒子等）：命中需写一句保留理由，写不出就换。需求点名的直接用。

### 第 5 步：规范构建（质量底线）

**结构与对齐**

- 页面头完整：`lang="zh-CN"`、charset、可区分多项目的 title；移动端必须声明 `<meta name="viewport" content="width=device-width, initial-scale=1">`。内容图写 alt，纯装饰图用空 alt。
- 对齐与栅格按 `references/alignment-grid.md` 执行：布局尺寸取 4 的倍数（安全区、媒体比例和响应式计算等必要例外除外）；页头、导航、Tab、筛选、卡片、表格左缘共享同一 x 坐标；多列结构用 CSS Grid，不用 flex 百分比凑数；大屏模块间隙全屏一档；数字右对齐等宽。违反按 A 级缺陷处理。
- 工作台双栏避免一侧不断堆叠、另一侧大面积闲置导致主要操作落到很下面；先调整分区、间距与次要内容展开方式，不靠拉高空面板或塞入无关内容凑等高。

**交互与无障碍**

- 语义结构：每页一个 h1，标题层级不跳级；导航、列表、表格用语义标签。
- 触控目标移动端 ≥44×44px、桌面 ≥32px；按钮主次分明，提供 hover/active/disabled，异步动作增加 loading，不给普通导航制造加载过程。
- 全部交互可键盘到达，焦点环始终可见；弹窗与抽屉做焦点管理。
- 表单 label 在输入框上方且与控件关联，错误就近提示，不用 placeholder 冒充 label。
- 异步或可变数据区按实际情况设计 loading/empty/error；静态内容不制造三态。有表单、检索、删除或提交时读取 `references/interaction-states.md`。
- 状态用语义色 + 文字/图标双通道表达。

**图标、动效与文案**

- 图标只来自一套主流图标库（Tabler / Lucide / Iconify 等）：经 CDN 引入，或用 better-icons 等工具从图标库导出的 SVG 均可；禁止凭印象手绘或拼凑 path。描边与视觉尺寸统一；图标名与授权按 `references/font-icon-selection.md` 核对。
- 动效只动 `transform`/`opacity`，交互反馈 150–300ms，缓出 `cubic-bezier(0.16,1,0.3,1)`，尊重 `prefers-reduced-motion`。
- 循环动效只用于加载与刷新过程（spinner、骨架屏），结束即停。在线、实时、连接正常等状态用静态的色、形、文字表达，不加循环闪烁、呼吸或跳动的红点，也不给色条、边框、标题等常驻元素加周期性明暗动画；大屏点位注意力动效按其形态专项条款处理。
- 文案主动语态：按钮写动作，错误写原因和补救；业务语汇具体真实。
- 数据可信：汇总与分项对得上账，百分比标基数，趋势标时间范围。

**技术栈、资源与媒体**

- 按项目现有框架与构建方式实现。单文件 HTML、指定地图库、固定分辨率缩放等仅在项目明确要求时执行；固定分辨率缩放比按 `min(可用宽/画布宽, 可用高/画布高)` 计算。
- 使用地图瓦片、外部图片、网页字体、CDN 脚本或视频时，按 `references/external-resources.md` 处理加载判定、视频净画面与内容图来源。
- 视频与封面比例按 `references/media-ratios.md`；地图与图表不套用视频比例。
- 图表按 `references/data-visualization.md` 选型。
- 需要查阅组件、色彩、排版、布局等通用规范时，从 `references/harmony/INDEX.md` 按任务定位文件，不整目录加载。
- 需要中文网页字体或图标 CDN 时，`online-fonts-icons` 技能可用则按 `references/font-icon-selection.md` 的索引读取对应参考；不可用时直接取该文件的自包含候选，不猜包名、候选不超过 2 个地址即回退系统栈，并在交付说明中如实记录。

### 第 6 步：分级验证

**功能缺陷类——必须修复并复测，不受轮次限制：**
排查控制台错误、意外横向溢出、资源加载、控件行为、相关状态与键盘可达。至少实际操作主流程及主要失败恢复路径；检查短文字意外换行、输入框挤压、图标文字重叠、固定栏遮挡及视频比例。移动 H5 另按目标容器验证（微信内置浏览器或对应移动 UA 下的布局、安全区与键盘弹出）。截图不能替代操作验证。验证前读取 `references/verification-notes.md`，避免文件拼接遗漏与工具假象。

**审美打磨类——限制轮次，防止无限打磨：**
一轮批量截图（桌面 + 移动一起拍）→ 一轮批量修复 → 最多再确认一轮后停手。配色微调、阴影深浅、间距偏好属此类。首轮截图先回看方向合同：页面是否回答了 THESIS、MEMORY 是否落地、色板字体是否来自 WORLD；不成立则同轮修复。

无法修复的功能缺陷必须如实写入交付说明，不许静默放过。
