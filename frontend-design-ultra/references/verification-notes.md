# 验证操作注意事项

第 6 步验证时读取本文件，避免因文件拼接错误或工具假象而误判、误改代码。

## 分段编辑后的完整性检查

- 分段生成或多次编辑写入的文件，验证前先通读拼接处：每次 Edit 之后重读接缝前后约 10 行。
- 确认 `<script>`、`<link>` 等关键标签没有整段丢失或重复。部分功能正常（如时钟在走）不能证明同文件其他块（如地图库标签）存在。
- Edit 锚点引用注释或邻接标签时，先确认锚点在磁盘上仍然存在，再执行编辑。

## 验证工具的已知假象

- CDN 资源做内容级检查，不只看 HTTP 200：地图瓦片、图链可能返回 200 但实为带水印的错误占位图；字体 CSS 可达不等于字形生效。应下载实际资源目检或截图确认。
- headless 截图存在已知问题：虚拟时间预算会使 rAF 补间动画计算出异常数值，CLI 截图可能裁切页面边缘。截图出现异常时，先用常驻浏览器实机复现，确认为页面真实问题后再修改代码。
- 动态数值、动画中间态、轮播暂停等，以实机浏览器验证结果为准。

## 网页字体生效确认

- 用目标中文调用 `document.fonts.load()`，确认返回非空 FontFace 且状态为 loaded，并通过 DevTools Rendered Fonts 核对实际字形。
- 仅 Promise 成功或 `document.fonts.check()` 返回 true，不能证明目标字体已生效。回退时如实记录。
