# 桌面工作台 / 后台专项流程

适用：PC 浏览器里的工作台、管理后台、编辑器、工具页（1280px 以上，键鼠操作，长时间使用）。属 Operate 模式：访客的成功是**完成任务**，不是被打动。

**核心判定标准：关键信息 3 秒可定位，操作路径可预期，久坐使用不疲劳。**

## 设计流程（按序执行）

1. **任务与角色梳理**：列出使用角色和本页要完成的 3–5 个高频任务，按频率排优先级。高频任务的入口必须最显眼。
2. **信息架构分区**：导航区（去哪）、工作区（干什么）、状态区（现在怎样）三块职责分明，不混排。
3. **布局骨架选型**：见下方模式库。骨架确定后再谈配色字体——工作台的风格分歧大多出在骨架选错。
4. **数据组件选型**：比较多条记录用表格（数字列右对齐、等宽数字）；监控状态用指标卡 + 趋势；层级数据用树或分组列表。含图表时按 `data-visualization.md` 执行选型、坐标轴与色彩规则；进度、占比环、范围类小组件参考 `harmony/05-components-display/data-panel.md`。
5. **状态设计**：按实际行为提供hover/active/disabled，异步操作有loading；可变数据区按需覆盖加载/空态/错误。按 `interaction-states.md` 实现输入保留、失败重试、撤销及列表/详情/数量联动；筛选、排序和页码状态可见。
6. **密度与节奏**：工作台密度取 8–48px 刻度；同屏模块用分隔线 + 留白分组优先，卡片只在需要表达独立实体时使用。

## 布局模式库

| 场景 | 推荐结构 |
|---|---|
| 多功能后台 | 顶部栏 + 左侧导航（可折叠）+ 主工作区 |
| 检索分析工作台 | 顶部筛选区 + 左侧结果列表 + 右侧详情/画布 |
| 单对象编辑 | 顶部标题与主操作 + 分区内联表单 + 右侧辅助面板 |
| 监控值班台 | 状态摘要条 + 主监控区 + 告警队列 |

## 质量底线

### 双栏内容与操作位置

工作台采用左右分栏时，两侧应围绕同一任务合理分配内容，避免一侧很长、另一侧很短，滚动后只剩半屏内容。允许主次和适量留白，不要求左右严格等宽、等高；重点是输入、操作和结果之间容易往返。

- 先保证常用输入与主要操作在目标桌面视口内容易找到，尽量让用户无需长距离滚动即可开始任务。根据可用高度安排内容，不把“首屏可见”变成缩小字体、压扁输入框或裁掉内容的理由。
- 输入侧过长时，优先收紧过大的上传区域和重复间距，将可并列的短参数排成行，低频参数放“高级设置”；不要把上传、长说明、全部参数、历史记录都纵向塞进一根窄栏。
- 历史记录按使用关系放在结果区的次级标签、可展开区域或双栏下方的独立区域，不默认接在输入表单底部。不能为了填右侧空白随意搬入无关模块。
- 结果尚未生成时，空状态保持简短，与工作区尺度协调；不能把短空态框强行拉到左栏一样高，制造更大的空白。先解决输入栏过长及整体分区，再安排空状态。
- 结果很多时，分页、按需展开或在适合的固定工作区内滚动；只有需要两侧持续对照时才采用独立滚动，保证滚动区域清楚、键盘可达，不默认制造多重滚动条。必要的粘性操作栏不能遮挡最后一项内容。
- 宽度或高度不足时，允许改成上下布局、顶部紧凑输入加下方结果等结构，不固守左右两栏。小屏、浏览器缩放和较长文本仍需完整可用。
- 检查初始空态、少量结果、大量结果和参数展开状态。若滚动到主要操作处时另一侧已完全空白，应重新检查分区；不要只检查有结果的理想截图。

例如“上传并检索”工作台：输入区保留适度大小的上传框、描述、常用参数和开始按钮；次要参数按需展开，历史记录独立安排；结果区承担预览与结果浏览。具体尺寸由内容和视口决定，不固化左右比例。

### 通用检查

- 对齐与栅格按 lignment-grid.md 执行：布局用 12 列 CSS Grid（断点 12/8/单列），页头/导航/Tab/筛选/卡片/表格左缘共享同一 x 坐标，卡片内边距与模块间隙各一档，尺寸取 4 的倍数；违反按 A 级缺陷处理。
- 页面标题跟随主内容起始轴，品牌标识与页面标题分工明确，不为统一布局强迫所有站点标题置于左上角。
- 按 `progressive-help.md` 精简说明：参数解释放就近帮助入口，重复说明合并，空状态保留一句当前状态和必要下一步；不把功能完整理解为每个字段都附说明段落。
- 数字用等宽或 `tabular-nums`，多列数字右对齐，千分位分隔；单位降一级灰色。
- 表格行高一致，表头固定可预期；操作列按钮文字化（"编辑/停用"），不堆图标。
- 全页键盘可达，焦点环可见；弹窗打开后焦点进入弹窗，关闭后回到触发元素。
- 容器桌面端居中收敛（1200–1400px），超宽屏主工作区可弹性拉伸但文本列不超 80 字符宽。
- 交互反馈 150–300ms；工作区不用入场编排动画（每天看一百遍的东西不许演）。在线、连接正常、数据实时这类状态用静态色形文字表达，不加循环呼吸或闪烁的点；表格与指标里的刷新提示在完成后停止。
- 按真实影响处理删除/停用/重置：可逆低风险操作优先直接执行加撤销，不可逆或高影响动作先说明后果并确认。

## 本形态反模式

- 营销页手法入侵：大标题大字、巨型 Hero 图、滚动叙事——浪费首屏工作面积；
- 一切内容套同款圆角卡片 + 同款灰阴影，层级消失；
- 每个面板加投影、每个区块加边框，视觉噪音大于信息；
- 图标按钮无文字且无 tooltip，新用户无法学习；
- 把移动端底部 Tab 搬上桌面。
