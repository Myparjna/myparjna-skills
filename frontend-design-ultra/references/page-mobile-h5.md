# 移动端 H5 专项流程

适用：手机浏览器、微信内置浏览器打开的 H5 页面，375–430px 宽度优先设计。与桌面页面的根本差异：视距约 30cm、单手握持为主、拇指触控、碎片时间、可能弱网。

**核心判定标准：产出必须"像移动端"，不是缩小版的桌面页。**

## 设计流程（按序执行）

1. **主任务收敛**：手机上用户一次只想干一两件事。写下本页唯一主任务和最多两个次任务，其余全部降级为入口或收起。
2. **拇指热区规划**：核心操作落在屏幕中下 2/3 的单手可达区；顶部放信息与导航，不放高频操作。避免多指手势。
3. **导航架构选型**：多栏目用底部 Tab（≤5 个，当前项明确高亮）；单任务页用顶部标题栏 + 返回。禁止把桌面侧边栏搬到手机。
4. **内容流组织**：主任务以纵向流为主；商品、相册或可独立扫读的短指标可按可用宽度用两列。长标签、输入表单和复杂操作优先单列，不为两列缩小文字或挤扁控件。避免意外横向滚动，明确的横滑组件保留可达操作。
5. **详情与层级**：详情用新页面或半屏弹窗（half-sheet），避免页面内层层展开造成迷失；返回行为可预期。
6. **反馈与状态**：触控反馈即时；异步加载按需要反馈，成功用局部更新/轻提示。按 `interaction-states.md` 处理失败恢复、输入保留与撤销；不可逆或高影响动作说明后果后确认。状态用静态色形文字表达；在线、存活、实时、连接正常不加循环闪烁或跳动的红点，严重度色条与卡片装饰不加周期性明暗动画，循环动效只用于加载与刷新过程。

## 布局模式库

| 场景 | 推荐结构 |
|---|---|
| 多栏目应用首页 | 顶部搜索/状态 + 内容卡片区 + 底部 Tab |
| 任务处理列表（告警/工单） | 优先级排序列表 + 状态色条 + 右滑或点进详情 |
| 单任务操作页 | 顶部标题栏 + 分组表单 + 底部固定全宽主按钮 |
| 数据摘要首页 | 关键指标卡（2 列）+ 趋势简图 + 待办列表 |
| 内容详情 | 标题区 + 正文流 + 底部操作栏（安全区内） |

## 质量底线

- 触控目标 ≥44×44px，间距优先 ≥8px；单任务表单的主按钮可全宽并固定底部，列表工具和多操作页面按任务就近放置，不强制每页固定全宽按钮。
- 正文字号 ≥14px，辅助文字 ≥12px；不使用浅灰小字承载关键信息。
- 全高流式页面用 `min-height:100dvh`（Tailwind `min-h-dvh` 或 `min-h-[100dvh]`，按项目版本选择）；固定应用容器可用 `height:100dvh` 配内部滚动，不能只换类名而忽略实际滚动布局。
- 适配安全区（`env(safe-area-inset-bottom)`），底部内容不被 Home 指示条遮挡。
- 图片用真实主题图链并加 `onerror` 兜底；首屏图片控制体积。
- 手势保持简单：点按、滑动为主，不依赖 hover，不用两指以上手势。
- 键盘弹出时输入框不被遮挡；表单 label 在输入框上方。
- 桌面查看并导入Figma的手机预览默认375px居中，窄窗口缩至可用宽度；真实H5按容器响应式，不把所有设备锁死375px。底部导航跟随应用宽度并为正文留空间。隐藏滚动条轨道时仍保留滚动、触摸、键盘与浏览器缩放。
- 视频画面遵守 `media-ratios.md`，竖向源优先9:16，不裁成扁条来迁就卡片高度。

## 本形态反模式

- 桌面三栏/侧边栏直接压缩进手机；
- 密集表格（超过 3 列的数据表在手机上应改为卡片或列表）；
- 悬浮球/悬浮按钮遮挡正文与主按钮；
- 桌面端装饰手法（大投影、复杂背景、视差）搬下来拖慢弱网加载；
- 字体层级超过 3 级，页面显得花。
